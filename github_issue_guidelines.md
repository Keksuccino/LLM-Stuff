# GitHub Issue Guidelines

- Never open, edit, or remove GitHub issues or comments on your own without the user explicitly telling you to do so.
- When writing an issue (bug report, feature request, etc.) always first check if there is a template for these in the target repository, and if so, closely mirror the template style, including adding the correct labels to the issue.
- Write issues in a compact and direct style, straight to the point without useless text slop. They should only contain the information that is actually needed, in a compact and direct way, while still staying friendly.
- If not told otherwise, always add a potential solution/fix or way of implementation to the issue.
- For comments use the same writing style as for issues.
- If useful, reference related issues in your own issue or comment.
- If a repository does not let you create issues or add labels when using the GitHub CLI or similar, open the issue via Chrome.
- If a repository forces you to add log files or similar to an issue, but in this specific case it is not possible or useless to add a log, you are allowed to use an empty placeholder file.
